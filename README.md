# TUM 日历控制

Android 本地优先的 TUM 课程同步与个人出席规则控制器。它将私有 iCal 中的来源课程按本地规则同步到应用自建的本机专用日历和／或 Google 次级日历，并由荣耀日历显示。

当前版本：`0.7.0`（构建号 `53`，课程子类型识别与本机改名；读取时间页可直接使用已保存课程）。完整迭代记录见 [VERSIONING.md](VERSIONING.md)。

展开课程后可在子类型旁点“改名”，首页、搜索、收藏及目录同步显示，并保存在本机；“恢复自动名称”撤销别名。名称仅用于显示，不修改日历内容。标题补充识别 VI 和 Praktikum／Projektpraktikum（PR），原已识别类型优先。读取时间页的“使用已保存课程 · 下一步”保存所选范围后直接进入选课，不发起读取；缓存范围外的课程仍需重新读取获取。

设置页可分别选择浅色的“清爽白／暖米白”和深色的“中性黑／深蓝”，模式与配色自动保存。跟随系统只切换明暗，使用各自选择的配色；不会改变课程出席的绿／蓝／灰语义。浮动导航和选课操作卡片保留自身不透明背景，内容在其背后滚动，不再为浮块裁短整页。

当前状态：功能已实现，待统一真人验收。用户主动读取私有 iCal 后可选择课程；成功读取会保留最近两份课程数据，写入前可明确选择使用上次成功读取或较早一次数据，并查看基于 UID＋实例键的更新说明。新课程默认蓝色“选择出席”，可单课或批量设为绿／蓝／灰并选择生效范围与收藏。点击“写入日历”后，应用会准备本机／Google 的影响数量，再由用户确认执行。

出席与收藏可选“统一设置”或“按课程分别设置”。分别设置按课程名称列出已选课次，默认保持原样，最后统一保存；公共生效范围适用于本次设置，收藏按所属课程生效。切换模式保留本页草稿，退出取消不保存，保存不直接写日历。

输出边界：本机端只使用应用创建的本地专用日历；Google 端只使用带固定所有权标记的应用次级日历，并请求最小的 `calendar.app.created` 范围。令牌仅存活在当前运行内。正常写入不删除旧课程；用户在“清理已写入日程”中明确选择范围并确认后，才会从应用专用目标清除带应用标记的日程，不会删除日历本身、主日历、订阅日历或用户其他日程。

确认写入后会逐条核对实际目标，再新增或更新；本机预计数量不代表日历已写入。Google 未就绪时可明确选择仅写入已就绪端。清理可单独选择目标，并只读补齐旧版已记录日程的详情；没有记录且无法确认身份的项目不能按名称接管。编辑课程字段影响同一来源 UID 的所有课次；出席状态可单独作用于具体课次。

读取范围现在会传给来源解析器；两端留空采用历史 120 天至未来 180 天，一端留空在所选端附近补齐约 300 天，单次最多五年，避免无限重复规则。已保存数据不因读取失败而丢弃，写入前不强制重新读取。

可选的后台 iCal 检查默认关闭；用户开启后也只会读取并比较加密摘要，绝不自动写日历。规则可经系统文件选择器备份／恢复，但备份不含私有订阅、账户、令牌、目标日历或事件映射，导入必须再次确认。

正式验收前仍需要：安装到荣耀真机、用户主动读取真实 iCal、授予本机日历权限、配置并完成 Google Android OAuth 授权、验证两目标的新增／更新／灰色截点／撤销及荣耀显示。上述每一步均需单独记录，不可由本机构建替代。

开始任何工作前后，必须阅读根目录 [AGENTS.md](AGENTS.md)。执行计划、验收结果与可复用规程只保存在本机 `.local-audit/`，不会纳入 Git 或 GitHub。

界面回归测试使用 Roborazzi：首次记录基线后必须人工查看 PNG；日常使用 `verifyRoborazziDebug` 验证，不得自动接受新的截图。

静态分析目前处于兼容性试验阶段：`lintCompatibilityReport` 只生成 Ktlint／Detekt 报告，不格式化、不改代码、不会阻断构建，也未接入 `check`。是否将其变为常规质量门禁，须待本机兼容性试验结果和后续人工决定。
